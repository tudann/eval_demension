## 一、统一输入形式

当前框架支持五种输入模式。每条 case 是 `input.root` 下的一个直接子目录。

|输入形式|当前读取的条件素材|主要用途|
|---|---|---|
|`t2va`|无首帧、无尾帧、无额外参考素材|只根据 prompt 和生成视频评估|
|`f2va`|`input_01` 作为首帧|检查视频是否从指定首帧开始|
|`l2va`|`input_02` 作为尾帧|检查视频是否结束在指定尾帧|
|`fl2va`|`input_01` 作为首帧，`input_02` 作为尾帧|同时检查首尾端点|
|`r2va`|按编号读取 `input_01`、`ref_video_01`、`ref_audio_01` 等参考素材|根据 prompt 中的引用关系评估参考素材使用情况|

默认 case 目录结构如下：

```text
<input.root>/
  case_001/
    prompt_final.txt
    video.mp4
```

带首尾帧时：

```text
<input.root>/
  case_001/
    prompt_final.txt
    video.mp4
    input_01.png
    input_02.png
```

`r2va` 模式下，参考素材使用编号规则：

```text
input_01.png
input_02.jpg
ref_video_01.mp4
ref_audio_01.wav
```

当前框架支持的常见扩展名包括：

- 图片：`.png`、`.jpg`、`.jpeg`、`.webp`
- 视频：`.mp4`、`.webm`、`.mov`、`.avi`、`.mkv`
- 音频：`.wav`、`.mp3`、`.flac`、`.m4a`、`.aac`、`.ogg`

## 二、统一评测流程

所有维度共用以下流程：

```text
输入 case
  -> 读取 prompt、视频和条件素材
  -> facts：提取需求事实
  -> checklist：生成 gates 和 items
  -> judge：回答 gates 和 items
  -> applies：判断子项是否适用
  -> 数值组件：执行当前启用且可运行的组件
  -> 合成子项分
  -> 合成维度分
  -> 输出单 case 和批次汇总
```

### 1. `facts`：需求事实

`facts` 是根据 prompt 提取的结构化信息，用于判断本条 case 需要评估哪些内容。

不同维度关注的事实不同：

- D13：目标风格、目标光照、目标颜色、参考图角色。
- D14：编辑目标、主体替换、添加物体、删除物体、视频续写、静态镜头。
- D15：对白、禁止人声、重复说话人、情绪、环境音、动作音效、配乐、参考音频。
- D16：对白、多人说话、音画事件、环境变化、真实感要求。
- D17：主体、主体名称、是否有人体、镜头运动要求。
- D18：目标文字、允许文字、字幕要求、字幕内容、禁止额外文字。

`facts` 不直接产生分数，主要决定子项和数值组件是否适用。

### 2. `gates`：评测门槛

`gates` 用来判断视频是否具备基本评测条件，不直接衡量质量。

当前各维度通常设置两道门槛，例如：

- 主体或画面是否清晰可见。
- 是否存在足够连续、可判断的内容。
- D15、D16 还会关注是否有可评估的音频或音画关系。

当前本地规则是：

- gate 明确通过：继续评估。
- gate 明确失败：可读取视频的维度总分记为 `1.0`，状态为 `gate_failed`，并纳入汇总均值。
- gate 没有有效回答：不直接视为明确失败，由回答状态保留该不确定性。
- 视频文件不存在：状态为 `skipped_missing_video`，不计分。

### 3. `items`：按 case 在线生成的检查题

每条 case 的 checklist 由在线裁判模型根据 prompt、输入模式和维度规则单独生成。生成阶段只读取 prompt 与输入素材信息来提取需求事实并编写题目，不检查生成视频；回答阶段才会根据视频或音频逐题作答。

统一约束如下：

- 每个 case、每个维度生成 **6–30 道**题；题目数量不足或超限的结果会被拒绝。
- 不要求覆盖该维度的所有子项，只检查 prompt 或输入模式明确表明适用的子项。
- 不得为了达到 6 道而增加不相关要求；适用要求较少时，应拆分为不同且可观察的检查方面。无法写出 6 道有效题时拒绝该 checklist，而不是虚构要求。
- 每题必须属于当前维度配置的合法子项；对于带 `applies` 条件的子项，事实不满足时不得生成该子项的题目。缺失事实按不适用处理。
- 题目不得重复，且必须能通过对应媒体判断；核心题最多 3 道。
- 支持 `yes_no`、`multiple_choice_3`、`multiple_choice_4`；选择题必须提供对应数量的选项，期望答案必须是合法选项 ID。
- 每道题带有 `id`、`subpoint`、`question`、`kind`、`expect`、`time_hint`、`weight`、`core` 和 `evidence_required` 等字段。

D13–D18 的策略边界如下：

- **D13 风格与视觉控制**：检查提示中明确提出的风格、风格持续性、风格与主体/动作的兼容性，以及明确的光照或色彩要求；不派生音频、编辑、文字或端点题。
- **D14 编辑与可控生成**：仅在提示或输入模式包含对应任务时检查局部编辑、非目标保持、主体替换、物体增删、视频续写或首尾帧；没有端点素材时不检查端点。
- **D15 音频质量与控制**：仅检查提示中存在的对白/禁语、可听语音、重复或参考音色、情绪、环境音、动作音效和配乐要求。
- **D16 音画同步**：仅检查明确的音画关系；口型同步要求对白和可见说话人，多说话人匹配要求多个说话人，音频变化同步要求具体动作或环境事件，真实感检查要求提示明确提出真实感。
- **D17 运动与时序一致性**：依据提示中出现的主体、动作、镜头运动和时序要求出题；只有画面中涉及人物时才检查人体运动，不派生音频或文字题。
- **D18 文本与视觉一致性**：依据明确的目标字符串、字幕、可读性/稳定性要求或禁止额外文字要求出题；不虚构字幕或目标文案。D18 facts 还会由本地结构校验，并用于驱动其 OCR 组件适用条件。

## 三、统一计分规则

### 1. Checklist 题目计分

同一子项下的有效题目按权重计算正确率：

```text
正确率 = 答对题目的权重之和 / 有效题目的权重之和
```

当前映射规则：

|加权正确率|Checklist 分|
|---:|---:|
|`1.00`|5 分|
|`0.80` 至小于 `1.00`|4 分|
|`0.60` 至小于 `0.80`|3 分|
|`0.30` 至小于 `0.60`|2 分|
|小于 `0.30`|1 分|

未回答题目默认不进入分母。

如果核心题答错，该子项最高为 2 分。

### 2. 数值组件计分

如果一个子项同时包含 checklist 和数值组件：

```text
子项分 = 已成功组件分数按配置权重加权后的平均值
```

以下情况不会直接当作 0 分：

- 当前 case 不满足适用条件：`not_applicable`。
- 组件所需输入不存在：`missing_input`。
- 模型或依赖未安装：`not_configured`。
- 组件执行失败：`error`。

只有成功获得分数的启用组件参与该子项的有效权重计算。

### 3. 维度总分

适用子项的分数取算术平均：

```text
维度分 = 所有适用且有分数的子项分数之和 / 适用且有分数的子项数量
```

不适用子项不进入维度平均。

### 4. 当前评测结果文件

每个 case 输出：

```text
facts.json
checklist.json
answers.json
result.json
```

每个批次输出：

```text
per_case.jsonl
summary.json
summary.md
```

## 四、第 13 维度：风格与视觉控制

第 13 维度判断视频是否符合目标风格，并检查风格在内容、光照、色彩和时间上的表现。

|二级评测项|评测内容|适用条件|可能涉及的数值组件|
|---|---|---|---|
|`style_accuracy` 风格准确性|视频是否呈现 prompt 要求的整体风格|默认适用|`csd_ref_similarity`：视频与合格风格参考图的相似度|
|`style_persistence` 风格持续性|风格是否在整个视频中保持稳定|默认适用|`csd_temporal_drift`：不同时间帧之间的风格漂移|
|`style_content_compat` 风格与内容兼容|风格化是否破坏主体、动作和世界状态|默认适用|`firm_world_consistency`：结构、动作和物理关系一致性|
|`lighting_control` 光照控制|是否执行白天、夜晚、逆光、冷暖光等要求|`facts.target_lighting` 为真|当前只有 checklist|
|`color_control` 色彩控制|是否执行指定颜色、色调和冷暖关系|`facts.target_colors` 为真|`palette_match`：CIE Lab 目标颜色匹配|

### D13 的数值组件说明

#### `csd_ref_similarity`

用于有合格风格参考图的 case。没有风格参考图时返回 `not_applicable`，不应把首尾帧自动当作 D13 的风格参考图。

#### `csd_temporal_drift`

用于检查视频在不同时间段的风格稳定性。它需要视频抽帧和风格特征计算能力。

#### `firm_world_consistency`

用于检查主体结构、动作连续性和物理关系。它不是普通的风格相似度指标，而是判断风格处理是否破坏视频内容。

#### `palette_match`

在 CIE Lab 色彩空间中比较目标颜色与视频像素的接近程度。没有明确目标颜色时不适用。

### 当前 D13 任务模板

当前 `task_d13_example.yaml` 纳入 CSD 的两个组件：有合格风格参考图时自动运行 `csd_ref_similarity`，视频满足抽帧条件时自动运行 `csd_temporal_drift`。`firm_world_consistency` 和 `palette_match` 全局关闭，因此不参与任何 case 的评估。

## 五、第 14 维度：编辑与可控生成

第 14 维度判断局部编辑、主体替换、物体增删、视频续写和首尾帧控制是否符合要求。

|二级评测项|评测内容|适用条件|可能涉及的数值组件|
|---|---|---|---|
|`local_edit_accuracy` 局部修改准确性|是否修改了指定目标，且过程和结果正确|`facts.edit_targets` 有内容|当前只有 checklist|
|`non_target_preservation` 非目标区域保持|背景、布局和非目标对象是否保持|默认适用|`dino_bg_consistency`、`masked_lpips_static`|
|`subject_replacement` 主体替换一致性|替换后的主体是否保持身份和结构合理|`facts.has_subject_replacement` 为真|`arcface_identity_keep`|
|`add_remove_object` 增删物体|要求添加的物体是否出现，要求删除的物体是否消失|`facts.add_objects` 或 `facts.remove_objects` 有内容|`gdino_presence`|
|`video_extension` 视频延长|续写视频是否与源视频自然衔接|`facts.is_continuation` 为真|`continuation_seam_lpips`|
|`first_last_frame` 首尾帧控制|生成视频端点是否符合输入条件图|有首帧或尾帧|`endpoint_psnr`、`endpoint_lpips`|

### D14 的数值组件说明

#### `dino_bg_consistency`

比较编辑目标之外的背景和非目标区域是否保持一致。通常需要先得到编辑目标区域，因此可能依赖目标检测结果。

#### `masked_lpips_static`

只对相对静止的镜头比较非目标区域感知差异。镜头运动明显时不适用。

#### `arcface_identity_keep`

用于人物主体替换时比较人脸身份特征。非人物主体不适合使用该组件。

#### `gdino_presence`

逐个检测添加或删除目标物体在视频末段是否出现或消失。

#### `continuation_seam_lpips`

比较生成视频首帧与源视频尾帧、参考视频尾帧或其他可用源帧之间的感知差异。

#### `endpoint_psnr` 和 `endpoint_lpips`

用于首尾帧模式：

- `f2va`：比较生成首帧和输入首帧。
- `l2va`：比较生成尾帧和输入尾帧。
- `fl2va`：两端都比较。
- `t2va`：不适用。
- 没有端点图的 `r2va`：不适用。

### 当前 D14 任务模板

当前 D14 模板关闭 DINO、遮罩 LPIPS 和 GroundingDINO 目标存在性组件；ArcFace、续写 LPIPS 和首尾帧组件保留了条件触发配置。真实模型是否可以运行，仍取决于本地模型和依赖是否安装。

## 六、第 15 维度：音频质量与控制

第 15 维度判断对白、语音自然度、音色、情绪、环境音、动作音效和配乐。

|二级评测项|评测内容|适用条件|可能涉及的数值组件|
|---|---|---|---|
|`dialogue_accuracy` 对白准确性|生成对白是否符合要求|有对白或明确禁止人声|`asr_cer`；禁止人声时可依赖 VAD|
|`voice_naturalness` 语音自然度|声音是否自然，是否有明显合成噪声|通常适用于有对白视频|`dnsmos_ovr`|
|`timbre_consistency` 音色一致性|同一说话人或参考音色是否稳定|重复说话人或有参考音频|`ecapa_same_speaker`|
|`emotion_control` 情绪控制|语音情绪是否符合要求|`facts.dialogue_emotions` 为真|`emotion2vec_match`|
|`ambient_sound` 环境音|雨声、风声、街道声等是否匹配|`facts.ambient` 有内容|`clap_ambient`|
|`action_sfx` 动作音效|脚步、碰撞、开门等声音是否匹配|`facts.sfx` 有内容|`clap_sfx`|
|`music_match` 配乐匹配|是否出现要求的配乐，或是否错误出现被禁止的配乐|要求有配乐或禁止配乐|`music_presence`、`clap_music`|

### D15 的数值组件说明

- `asr_cer`：使用自动语音识别结果与目标对白比较。
- VAD：用于禁止人声检查，也可以为语音质量组件提供语音片段。
- `dnsmos_ovr`：评估语音自然度。
- `ecapa_same_speaker`：比较不同语音段的说话人声纹一致性。
- `emotion2vec_match`：比较语音表现与目标情绪。
- `clap_ambient`：比较环境音与文本描述。
- `clap_sfx`：比较动作音效与文本描述。
- `music_presence`：判断是否存在音乐。
- `clap_music`：判断配乐与描述或参考音频是否匹配。

### 当前 D15 任务模板

当前 `task_d15_example.yaml` 全局关闭 `asr_cer`，但纳入 `dnsmos_ovr`、`ecapa_same_speaker`、`emotion2vec_match`、`clap_ambient`、`clap_sfx`、`music_presence` 和 `clap_music`。这些组件只在对应需求事实成立时自动运行；没有对白、参考音色、情绪、环境音、动作音效或配乐要求时分别跳过。VAD 只作为按需内部依赖，不作为独立评分项。

## 七、第 16 维度：音画同步

第 16 维度判断对白口型、多人说话人、动作音效、环境变化和整体音画真实感。

|二级评测项|评测内容|适用条件|可能涉及的数值组件|
|---|---|---|---|
|`lip_sync` 口型同步|口型是否与对白同步|`facts.dialogues` 为真|`syncnet_conf`|
|`multi_speaker_match` 多人说话人匹配|声音是否对应正确人物|`facts.multi_speaker` 为真|`syncnet_voiceover_still`|
|`audio_change_alignment` 音频变化同步|环境或音效变化是否与画面事件同步|`facts.av_events` 或 `facts.env_changes` 为真|当前主要使用 checklist|
|`realism` 音画真实感|音画结合是否自然合理|`facts.realistic` 为真|当前主要使用 checklist|

### D16 的数值组件说明

- `syncnet_conf`：检查人物口型和对白之间的同步关系。
- `syncnet_voiceover_still`：检查画外音或静止人物场景中的声音与画面关系。
- 音频变化、环境变化和真实感目前主要通过 checklist 评估。

### 当前 D16 任务模板

当前 D16 模板关闭 SyncNet 数值组件，默认使用 checklist。没有对白、多人说话或相关音画事件时，对应子项不适用。

## 八、第 17 维度：运动与时序一致性

第 17 维度判断动作、镜头、主体身份、时间连续性和人体运动是否稳定。

|二级评测项|评测内容|适用条件|可能涉及的数值组件|
|---|---|---|---|
|`motion_consistency` 运动一致性|动作是否连续，是否有突发异常|默认适用|`vlm_anomaly_rate`|
|`camera_motion` 镜头运动控制|镜头运动是否符合 prompt|`facts.requested_camera_motion` 为真|`vmbench_ois`|
|`subject_consistency` 主体一致性|主体身份、外形和结构是否稳定|`facts.subjects` 有内容|`vmbench_mss`|
|`temporal_continuity` 时间连续性|前后帧是否连续，是否有跳变和瞬移|默认适用|`vmbench_tcs`|
|`human_motion` 人体运动|手脚、身体和人体动作是否自然|`facts.has_humans` 为真|`skeleton_blc_cv`|

### D17 的数值组件说明

- `vlm_anomaly_rate`：统计异常事件或异常时间片段比例。
- `vmbench_ois`：检查主体或物体完整性。
- `vmbench_mss`：检查运动平滑度和主体运动稳定性。
- `vmbench_tcs`：检查时间一致性。
- `skeleton_blc_cv`：根据人体关键点计算肢体运动稳定性。

这些组件可能共享检测、异常时间线或人体关键点等中间结果，但在当前本地框架中默认关闭，避免本地没有模型时隐式启动外部模型。

### 当前 D17 任务模板

当前 `task_d17_example.yaml` 纳入 `vlm_anomaly_rate`，用于 gate 通过后的运动异常时间线评估。VMBench 和人体骨架组件保持全局关闭，因此不运行 `vmbench_ois`、`vmbench_mss`、`vmbench_tcs` 和 `skeleton_blc_cv`。

## 九、第 18 维度：文本与视觉一致性

第 18 维度判断目标文字、字幕、文字可读性、文字稳定性和额外文字控制。

|二级评测项|评测内容|适用条件|可能涉及的数值组件|
|---|---|---|---|
|`text_accuracy` 目标文字准确性|目标文字是否正确，有无错字、漏字和乱码|`facts.expected_texts` 有内容|`ocr_cer`|
|`subtitle_alignment` 字幕完整性与对齐|字幕是否完整、顺序正确并与内容对应|`facts.subtitles_required` 为真|`ocr_subtitle_alignment`|
|`text_readability` 文字可读性|字体、大小、清晰度和排版是否便于阅读|有目标文字或字幕要求|`ocr_readability`|
|`text_stability` 文字稳定性|文字是否闪烁、漂移、变形或消失|有目标文字或字幕要求|`ocr_text_stability`|
|`no_unrequested_text` 无额外文字|是否出现未要求的字幕、水印、杂字|默认适用|`ocr_unexpected_text_rate`|

### D18 的数值组件说明

- `ocr_cer`：比较 OCR 识别文字与目标文字的错误率。
- `ocr_subtitle_alignment`：检查字幕流的顺序和内容对齐。
- `ocr_readability`：根据 OCR 置信度和文字尺寸评估可读性。
- `ocr_text_stability`：比较连续帧中目标文字的出现和稳定程度。
- `ocr_unexpected_text_rate`：统计未要求文字出现的帧比例。

多个 OCR 子项可以共享一次视频抽帧和 OCR 识别结果。

### 当前 D18 任务模板

当前 `task_d18_example.yaml` 纳入 `ocr_cer`、`ocr_subtitle_alignment`、`ocr_readability` 和 `ocr_text_stability`。这些组件由目标文字和字幕事实自动判断是否运行。`ocr_unexpected_text_rate` 全局关闭，因此不对任何 case 进行额外文字 OCR 扫描。

## 十、当前任务模板的实际范围

当前六份任务配置不是完整模型部署配置，而是本地无远端服务情况下的保守运行配置：

|维度|当前默认评估方式|任务模板中数值组件状态|
|---|---|---|
|D13|Checklist + 条件性 CSD|CSD 参考相似度和时间漂移开启；FIRM、palette 全局关闭|
|D14|Checklist 加条件性端点/身份/续写组件接口|DINO、遮罩 LPIPS、GroundingDINO 默认关闭；部分轻量组件保留配置入口|
|D15|Checklist + 条件性音频组件|ASR 全局关闭；DNSMOS、ECAPA、Emotion2Vec、CLAP 和音乐存在性组件纳入体系|
|D16|Checklist|SyncNet 默认关闭|
|D17|Checklist + 条件性异常时间线|VLM anomaly timeline 纳入体系；VMBench、骨架默认关闭|
|D18|Checklist + 条件性 OCR|目标文字、字幕、可读性、稳定性 OCR 纳入体系；额外文字 OCR 全局关闭|

“配置中存在某个组件”表示该组件属于评测方案并且可以被任务配置引用；是否在一次 case 中实际运行，还要同时满足：

1. 子项适用条件成立。
2. gate 通过。
3. 任务配置没有关闭该组件。
4. 组件输入和本地依赖存在。
5. 没有可复用的成功结果缓存，或使用了 `--force`。

## 十一、运行方式

例如运行第 13 维度：

```powershell
cd D:\git\kwkj-lt\v_eval
python .\run.py --task-config .\configs\task_d13_example.yaml
```

只运行检查阶段：

```powershell
python .\run.py --task-config .\configs\task_d13_example.yaml --stages check
```

强制重新计算：

```powershell
python .\run.py --task-config .\configs\task_d13_example.yaml --force
```

当前第 13–18 维度均使用在线裁判服务生成 checklist 并回答题目；未配置对应在线服务时会报配置错误，不会切换到离线规则或本地自动生成题目。Checklist 生成和媒体回答可以配置不同的 OpenAI 兼容服务。常用环境变量如下：

```bash
export V_EVAL_CHECKLIST_URL='http://127.0.0.1:8011/v1'
export V_EVAL_CHECKLIST_MODEL='your-checklist-model'
export V_EVAL_CHECKLIST_API_KEY='your-api-key'
export V_EVAL_VISION_JUDGE_URL='http://127.0.0.1:8012/v1'
export V_EVAL_AUDIO_JUDGE_URL='http://127.0.0.1:8013/v1'
export V_EVAL_AUDIO_JUDGE_MODEL='your-audio-model'
python run.py --task-config configs/task_d13_example.yaml
```

如果 checklist 和回答阶段共用同一服务，也可以设置 `V_EVAL_JUDGE_URL`、`V_EVAL_JUDGE_MODEL` 和相应 API key。D13、D14、D17、D18 使用视觉裁判；D15 使用音频裁判；D16 使用音画联合裁判。媒体回答阶段返回的有效 answers 才会参与 checklist 计分。

运行前应确认 `.env` 或进程环境中已配置适用于该维度的在线服务。生成完成后，可检查每个 case 的 `facts.json`、`checklist.json`、`answers.json` 和 `result.json`；需要重跑时使用 `--force`。
