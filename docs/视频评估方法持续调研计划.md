> 更新日期：2026-10-29（§1 各表增加「评估原理」列；此前 10-27 已按开源质量复筛，§2 同步收敛）  
> 目标：在现有 **20 维评估框架**（D1–D18、D20；D19 成本维不计）之上，持续跟踪两类新工作——**整体评估框架**与**分维度专项方法/指标**——形成可落地的调研与接入计划。

## 0. 调研范围与原则

### 0.1 两条调研线

| 线路 | 定义 | 典型例子 | 对现有框架的用途 |
|------|------|----------|------------------|
| **A. 整体评估框架** | 整套 benchmark（见 §1：长时交互流式 / 通用 T2V·裁判 / 条件·编辑·AV） | StreamEval、VBench、OmniVBench、IVEBench、OpenS2V 等 | 借鉴协议设计、任务分层、指标聚合、人机对齐；择优做旁路对照或增量接入 |
| **B. 分维度专项** | 针对单一能力（物理、运动、口型、字幕、编辑保真等）的 benchmark / 指标 / 裁判模型 | VideoPhy-2、TRAJAN、IVEBench、TextVBench、AV-HuBERT sync | 补强对应一级/二级维的数值组件、检查题设计、人工校准 |

### 0.2 开源质量门槛（本次复筛）

按 GitHub 星数与套件完整度收敛清单（约 2026-10 快照）：

| 档位 | 标准 | 处理 |
|------|------|------|
| **主清单** | 约 ≥30★，或社区基线（VBench/DOVER/VideoScore/T2V-CompBench/VideoPhy 等），或本地已用（OmniVBench/StreamEval），或机构完整开源（如 MS AVGen） | 保留；可试点者优先 |
| **仅协议/观察** | 论文有用但开源弱、或任务形态不符 | 不进复现主路径 |
| **已剔除** | ★≲20 且无特殊理由，或评测代码/资产明显残缺 | 移出主表（见文末备注） |

本次因低星/残缺移出或降级的包括：**VideoArgus（~9★）**、**THEval（0★）**、**Ref4D-VideoBench（~2★）**、**MSAVBench（~6★）**、**IsoVRBench / GT-SVJ（几乎无社区采用）**，以及一批「仅有论文、无可跑套件」条目（RAVEN/RewardVerse/EvalVerse/VGA/VABench/AVBench/V2V/VEFX/DrivingGen 等）。

### 0.3 与现有 20 维的对齐方式

每条外部工作需登记：

1. **对应维度**：一级维（及可选二级子项）
2. **测的是什么**：协议 / 指标定义 / 是否需要参照
3. **能否迁移**：直接接入数值组件 / 改造检查题 / 仅作旁路对照 / 暂不迁移
4. **开源状态**：数据、代码、权重、许可
5. **优先级**：P0（立刻精读+试点）/ P1（本季度）/ P2（观察）

### 0.4 产出节奏（建议）

按 §3 流程推进，不按周次排项目；节奏上可参考：

| 周期 | 产出 |
|------|------|
| 持续 | 新文献过 §0.2 后入库；对在办条目做精读判断（可复现 / 仅借鉴 / 搁置） |
| 有结论即落地 | 可复现 → 框架对照跑分；可挂维 → 嵌入该维做验证测试 |
| 滚动 | 更新精读/落地结论；校准通过后再考虑改对外维度规则 |

## 1. 整体评估框架调研清单

> 本节按**任务形态**分桶。表内仅保留通过 **§0.2 质量门槛** 的工作。  
> **接入判断**：可试点接入 / 仅借鉴协议 / 暂不接入（含义同前）。  
> **评估原理**列只写打分机制：看什么证据、怎么变成分数。  
> **开源情况**列统一写清五件事：**代码入口**、**数据/题库**、**权重或裁判模型**、**许可**、**复现注意**（缺什么、依赖多重）。

### 1.1 长时交互与流式生成评测

评测对象：生成过程中持续有输入、会话较长（多轮 / 流式 / 世界模型 / 长视频）。  
说明：现有框架主路径仍是「提示词 + 生成视频 + 可选参考」的短 clip；下列工作以**协议借鉴**为主。

| 工作 | 时间 | 要点 | 评估原理 | 开源情况 | 接入判断 |
|------|------|------|----------|----------|----------|
| **StreamEval** | 2026-10 | 交互流式 5 任务×10 指标；15–300s | 长会话里输入按时间逐步放出。视觉裁判只报结构化缺陷，固定规则折成 0–100 的机会成功率：该执行的控制、该保持的状态、该对齐的口型，未完成的机会留在分母里 | **代码**：[StreamEval/StreamEval](https://github.com/StreamEval/StreamEval)（评测调度、裁判、计分；本地已克隆）。**数据**：HF/ModelScope `StreamEval/StreamEval`（cases/oracles/源媒体；bench 约 300 条件）。**协议**：`docs/evaluation.md` + `evaluation/protocol/*.json` 机器可读规则。**许可**：代码 Apache-2.0；数据 CC BY 4.0（编辑源片保留第三方许可）。**注意**：需按 WebSocket 协议起模型服务；跑全量依赖 GPU/多环境，且任务是长会话流式，与短 clip 主路径不同 | **仅借鉴协议**。指标可对照 D1/D4/D12/D14–D16/D20；整套会话调度不宜进短 clip 回归。本地仓可做 1–2 条旁路 |
| **WBench** | 2026-05 | 多轮世界模型；5 维×22 子指标 | 多轮交互按画质、设定遵循、交互遵循、一致性、物理五维计分。画质用感知指标；场景/主体/动作类交互用 VLM 逐条核对；导航用估计相机位姿对照由动作合成的轨迹。子指标线性拉到 0–100 | **代码**：[meituan-longcat/WBench](https://github.com/meituan-longcat/WBench)（评测脚本 + 接入示例）。**数据**：完整题库与交互回合已公开发布（README 称 full/navi；HF 有官方榜入口）。**权重**：评测依赖的若干感知/几何组件随仓或说明提供。**许可**：MIT。**注意**：面向世界模型导航/多轮控制，依赖链含 SAM/深度/光流等，工程偏重 | **仅借鉴协议**。物理/镜头子项对照 D7/D9；导航/6-DoF 非主任务 |
| **WorldScore** | 2025 | next-scene + 相机轨迹；可控/质量/动态 | 世界生成拆成「当前场景 + 下一镜文案 + 指定相机轨迹」的逐步下一镜。可控性看估计轨迹与给定轨迹的旋转/平移误差、指定物体是否被检出、整段文案的 CLIP 对齐；质量和动态用美学与运动指标，静/动世界分开汇总 | **代码**：[haoyi-duan/WorldScore](https://github.com/haoyi-duan/WorldScore)（评测管线）。**数据**：项目页/仓内提供评测用场景与相机轨迹设定。**权重**：需自备/下载 SAM、DINO 等第三方权重。**许可**：MIT。**注意**：完整榜例多、依赖重组装成本高；适合只摘运镜/可控子度量 | **可试点接入（窄）**：运镜/空间子度量旁路 D8/D9 |
| **VBench-Long** | 2024–2025 | 长视频上 VBench 时序/美学 | 沿用 VBench 的时序与美学指标，在长视频上按片段抽帧计分（闪烁、运动平滑、主体/背景一致、美学/成像），用来抓住短 clip 上看不见的漂移 | **代码/数据/权重**：不单独立项，随 [Vchitect/VBench](https://github.com/Vchitect/VBench) 主仓（长视频抽帧与时序/美学维度同一套工具）。**许可**：Apache-2.0。**注意**：先装通 VBench 再开长视频配置 | **可试点接入**：与 D3/D4 数值组件同源 |

**StreamEval 补充**：已克隆仓库。建议只做「10 指标 ↔ 20 维」对照 + 可选旁路，不替代现有 1–5 分协议。

### 1.2 通用 T2V/I2V 能力与裁判协议

| 工作 | 时间 | 要点 | 评估原理 | 开源情况 | 接入判断 |
|------|------|------|----------|----------|----------|
| **VBench / ++ / 2.0** | 2024–2025 | 通用多维 + 内在忠实度 | 每维一套专用自动器。1.0/++ 用 DINO、CLIP/ViCLIP、美学预测器、MUSIQ、光流、插帧先验和检测器，分别量主体/背景一致、画质、运动和文案对齐。2.0 改问内在忠实：VLM 做描述对齐和是非题，并加人体异常等专项检测，覆盖人体、物理、常识、可控和创意 | **代码**：[Vchitect/VBench](https://github.com/Vchitect/VBench)（统一实现 VBench / ++ / 2.0）。**数据**：仓内 Prompt Suite + 各维评测方法套件。**权重**：美学/成像/语义等第三方 ckpt 按官方脚本下载。**许可**：Apache-2.0。**注意**：首次环境与权重体积大，但是社区默认基线，文档与 issue 成熟 | **可试点接入**：已部分吸收；VBench-2.0 物理/人体题可加强 D7/D17 |
| **VideoScore / VideoScore2** | 2024–2025 | 多维裁判；CoT 三维 | 用人工多维分训练视频裁判，直接回归分数近似人评。VideoScore 出画面质量、时序一致、动态程度、文视频对齐、事实一致。VideoScore2 先写理由再打分，收敛为画面质量、文本对齐、物理/常识一致 | **代码**：[TIGER-AI-Lab/VideoScore](https://github.com/TIGER-AI-Lab/VideoScore)、[VideoScore2](https://github.com/TIGER-AI-Lab/VideoScore2)（推理与评测脚本）。**数据**：HF `TIGER-Lab/VideoFeedback2`（约 2.7 万条人工分+推理迹）；另有 VideoScore-Bench-v2 等。**权重**：HF 可下载 VideoScore / VideoScore2 裁判模型。**许可**：MIT（以仓内为准）。**注意**：作旁路打分即可，不必重训；需 GPU 推裁判 | **可试点接入**：D2/D7 旁路裁判，与清单分对照 |

### 1.3 条件控制、编辑与音视频任务评测

评测对象：参考条件、视频编辑、音视频联合等。

| 工作 | 时间 | 要点 | 评估原理 | 开源情况 | 接入判断 |
|------|------|------|----------|----------|----------|
| **OmniVBench** | 2026-09 | R2V 因子清单 RF/IR/VQ | 参考生视频分三项。参考保真按本条激活的因素清单打 1–5，问该留的因素有没有留下；指令实现用另一份清单问该改的有没有改对、不该抄的有没有去掉；视频质量用三个现成模型打成片观感。三项等权 | **代码/复现**：本地 `OmniVBench/reproduce`（已跑通参考生路径）。**数据**：HF 发布题目与参考素材（RF/IR/VQ 因子清单）。**权重**：裁判侧按本地配置接 VLM/清单，无单独必装「Omni 专用」大权重。**注意**：继续作 D12–D14 旁路；勿把无关维分数混进对外维 | **可试点接入**：D12–D14 主旁路；不混入无关维对外分 |
| **IVEBench** | ICLR 2026 | 指令编辑；质量/遵循/保真 | 编辑结果拆成三条。成片质量用主体/背景一致、闪烁、运动平滑和训练画质分；指令遵循用视频–文本嵌入相似度，辅以 MLLM；保真比较源片与成片的语义和运动，并对不该改的内容让 VLM 打 1–5 分 | **代码**：[RyanChenYN/IVEBench](https://github.com/RyanChenYN/IVEBench)（评测与榜更新）。**数据**：HF `Coraxor/IVEBench`（约 600 源视频 + 编辑指令 taxonomy）。**权重**：传统指标 + MLLM 评估，按 README 配模型/API。**许可**：见仓内。**注意**：D14 首选开源对照；可先子集跑质量/遵循/保真三轴 | **可试点接入**：D14 首选开源对照 |

## 3. 落地执行计划

整体不做按周排期，按下面流程对 §1 / §2 清单逐条推进。

### 3.1 总流程

```
清单条目（§1 框架 / §2 分维）
        │
        ▼
  ① 精读与可落地判断
   · 代码/数据/权重是否齐、能否在现有输入（提示词+视频+可选参考）下跑通
   · 若不能复现：协议/指标/出题思路是否仍值得借鉴
        │
        ├─ 不能复现、也无可借鉴思路 ──► 搁置 / 移出主清单
        │
        ├─ 仅可借鉴思路 ──► 写入纪要；改造检查题或指标定义；不强制开源复现
        │
        └─ 可复现或可局部复现
                │
                ├─ 作为整套/旁路评估器可用
                │     ──► ②a 直接复现，用于评估后续生成框架（对照跑分）
                │
                └─ 可挂到现有某一（或某几）维度
                      ──► ②b 嵌入对应维（数值组件 / 旁路裁判 / 检查题），做小规模验证测试
```

两条落地路径可并行：同一工作既可以先做整套复现对照，再裁一块嵌进维度；也可以只做其中一条。

### 3.2 第一步：精读与可落地判断（对每条必做）

对照 §1「开源情况 / 接入判断」再确认一遍，输出简短结论即可：

| 结论 | 含义 | 后续动作 |
|------|------|----------|
| **可直接复现** | 开源齐、依赖可装、与现有评测输入兼容（或稍改即可） | 走 3.3 |
| **可局部复现** | 只能摘模块/子指标（如 AVGen 的 Sync、FilmOps 单算子） | 优先走 3.4 挂维；整套不勉强 |
| **仅借鉴思路** | 无可靠开源或任务形态差太远，但协议/taxonomy/出题有用 | 改检查题或纪要；不做工程复现 |
| **暂不跟进** | 低质量、残缺或与 20 维无关 | 搁置 |

精读时重点看：测的是什么、要不要参照、工程成本、与现有 1–5 分清单是否冲突。

### 3.3 路径 A：能复现 → 直接用于评估后续框架

适用：VBench / VideoScore2 / IVEBench / OmniVBench 等可跑通的 benchmark 或裁判。

1. 固定一小批 case（提示词 + 生成视频 + 可选参考）
2. 按该工作的官方协议出分或出报告
3. 与现有 20 维结果对照：相关性、是否多报/漏报、能否作为旁路门禁
4. 通过后再扩大到更多模型/版本的回归；**不替代**对外维度分，除非另行校准定稿

目标：有一套（或几套）可重复的外部评估器，用来衡量后续生成框架，而不是先改我们的维度规则。

### 3.4 路径 B：能嵌入某维 → 加入该维并验证测试

适用：指标或模块能明确对应 D1–D18 / D20（见 §2 挂接）。

1. 选定目标维与接入形态：数值组件 / 旁路分数 / 检查题模板
2. 接到现有该维评测流程，小样本跑通
3. 验证：与人工或现有清单是否同向、失败 case 是否可解释、成本是否可接受
4. 验证通过 → 保留为该维候选组件；不通过 → 退回「仅借鉴」或放弃

目标：把外部方法真正变成某个维度上的可测能力，而不是只停在文献表。
